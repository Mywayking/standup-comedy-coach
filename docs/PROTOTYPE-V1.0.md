## 1. 信息架构 IA

### 1.1 页面总览

| 页面 | 路由 | 职责 | 优先级 |
|------|------|------|--------|
| 首页 / 工作台 | `/` | 入口引导、发起创作 | P0 |
| 素材输入页 | `/create/material` | 用户输入生活素材 | P0 |
| 诊断结果页 | `/create/diagnosis` | 展示 AI 诊断结论 | P0 |
| 前提选择页 | `/create/premise` | 选择故事讲述方向 | P0 |
| 角度选择页 | `/create/angle` | 选择具体切入角度 | P0 |
| 包袱选择页 | `/create/punchline` | 选择段子零件 | P0 |
| 草稿生成页 | `/create/draft` | 生成并编辑最终稿 | P0 |
| 项目列表页 | `/projects` | 查看所有创作项目 | P0 |
| 项目详情页 | `/projects/[id]` | 查看单个项目全流程 | P0 |
| 设置页 | `/settings` | 创作偏好与数据管理 | P1 |

### 1.2 页面职责详解

#### 首页 / 工作台

| 项目 | 内容 |
|------|------|
| **核心职责** | 品牌展示、发起创作入口、历史项目入口 |
| **入口来源** | App 打开时默认到达；其他页面「←」返回 |
| **核心数据对象** | 无（纯展示） |
| **出口** | 「开始创作」→ 素材输入页；「我的段子」→ 项目列表页 |
| **异常状态** | 无 |

#### 素材输入页

| 项目 | 内容 |
|------|------|
| **核心职责** | 接收用户素材输入，为 AI 诊断提供原料 |
| **入口来源** | 首页「开始创作」|
| **核心数据对象** | `Project.material.content`（素材文本）|
| **出口成功** | → 诊断结果页（AI 诊断成功后自动跳转）|
| **出口失败** | → 停留在本页，显示错误 + 重试按钮 |
| **异常状态** | 字数不足（< 100字）、网络失败、AI 超时 |

#### 诊断结果页

| 项目 | 内容 |
|------|------|
| **核心职责** | 展示 AI 对素材的诊断结论，引导用户进入前提选择 |
| **入口来源** | 素材输入页「开始诊断」成功 |
| **核心数据对象** | `Project.diagnosis`（诊断 JSON）|
| **出口** | 「看看这些方向 →」→ 前提选择页 |
| **异常状态** | AI 无法提取喜剧元素（提示修改素材）|

#### 前提选择页

| 项目 | 内容 |
|------|------|
| **核心职责** | 用户从 3-5 个方向中选择一个最有感觉的前提 |
| **入口来源** | 诊断结果页 |
| **核心数据对象** | `WorkflowCard(step=premise)`；`Project.premise_id` |
| **出口** | 主按钮 → 角度选择页 |
| **返回** | 「← 返回诊断」→ 诊断结果页（已选前提保留选中态）|
| **异常状态** | 某卡片生成失败（单独显示重试）|

#### 角度选择页

| 项目 | 内容 |
|------|------|
| **核心职责** | 用户选择具体切入角度（可笑潜力标签辅助决策）|
| **入口来源** | 前提选择页 |
| **核心数据对象** | `WorkflowCard(step=angle)`；`Project.angle_id` |
| **出口** | 主按钮 → 包袱选择页 |
| **返回** | 「← 返回前提」→ 前提选择页（已选角度保留）|
| **异常状态** | 同上 |

#### 包袱选择页

| 项目 | 内容 |
|------|------|
| **核心职责** | 用户多选包袱零件，排列组合后生成草稿 |
| **入口来源** | 角度选择页 |
| **核心数据对象** | `WorkflowCard(step=punchline)`；`Project.selected_punchline_ids` |
| **辅助区域** | 草稿预览区（实时显示已选包袱顺序）|
| **出口** | 主按钮「生成草稿 →」→ 草稿生成页 |
| **返回** | 「← 返回角度」→ 角度选择页 |
| **异常状态** | 某包袱生成失败（单独重试，不阻塞其他）|

#### 草稿生成页

| 项目 | 内容 |
|------|------|
| **核心职责** | AI 组合包袱生成最终稿，用户可编辑、可保存、可标记完成 |
| **入口来源** | 包袱选择页 |
| **核心数据对象** | `Project.final_script`；`Project.status` |
| **出口成功** | 「标记为完成」→ 项目详情页（展示完整流程）|
| **出口编辑** | 留在本页，进入编辑模式 |
| **返回** | 「← 返回包袱」→ 包袱选择页（保留已选包袱）|
| **异常状态** | AI 无法组合包袱（提示调整包袱选择）|

#### 项目列表页

| 项目 | 内容 |
|------|------|
| **核心职责** | 展示用户所有创作项目（进行中 + 已完成）|
| **入口来源** | 首页「我的段子」；其他页面顶部入口 |
| **核心数据对象** | `Project[]` 列表 |
| **出口** | 卡片点击 → 项目详情页；「+ 新建」→ 素材输入页 |
| **异常状态** | 加载失败、空列表（引导创建第一个项目）|

#### 项目详情页

| 项目 | 内容 |
|------|------|
| **核心职责** | 展示单个项目的完整创作过程和最终稿 |
| **入口来源** | 项目列表页卡片点击 |
| **核心数据对象** | `Project` + `WorkflowCard[]` |
| **操作** | 继续创作 / 重新开始 / 复制稿子 / 删除项目 |
| **异常状态** | 项目不存在（返回列表）|

#### 设置页

| 项目 | 内容 |
|------|------|
| **核心职责** | 创作偏好设置、数据管理 |
| **入口来源** | 首页底部或个人中心入口 |
| **核心数据对象** | `UserSettings` |
| **异常状态** | 无 |

### 1.3 核心数据对象关系

```
Project (段子项目)
├── id, title, status, created_at, updated_at
├── material.content
├── diagnosis (Diagnosis)
├── premise_id → WorkflowCard(premise)
├── angle_id → WorkflowCard(angle)
├── selected_punchline_ids → WorkflowCard(punchline[])
└── final_script, word_count_final

WorkflowCard (工作流卡片)
├── id, project_id, step_type
├── title, content, metadata
├── selected, favorite
├── created_by: 'user' | 'ai'
└── version_history[]
```

## 2. 用户主路径 User Flow

### 2.1 完整主路径

```
首页
    ↓ [点击"开始创作"]
素材输入页
    ↓ [输入素材 ≥ 100字，点击"开始诊断"]
素材诊断中（loading）
    ↓ [诊断成功]
诊断结果页
    ↓ [查看诊断，选择方向，点击"看看这些方向"]
前提选择页
    ↓ [浏览卡片，选择 1 个前提，点击主按钮]
角度选择页
    ↓ [浏览卡片（可笑潜力标签辅助），选择 1 个角度，点击主按钮]
包袱选择页
    ↓ [浏览卡片，多选包袱，调整顺序，点击"生成草稿"]
草稿生成中（loading）
    ↓ [生成成功]
草稿生成页
    ↓ [查看稿子，可编辑，点击"标记为完成"]
完成保存中（saving）
    ↓ [保存成功]
项目详情页
    ↓ [可继续创作 / 可返回项目列表]
```

### 2.2 每一步详细说明

#### 步骤 0：首页

| 项目 | 内容 |
|------|------|
| **用户看到什么** | 品牌标题、主 CTA 按钮「开始创作」、次级按钮「我的段子」、底部提示语 |
| **用户点击什么** | 「开始创作」→ 素材输入页；「我的段子」→ 项目列表页 |
| **系统保存什么** | 无 |
| **失败时怎么处理** | 无失败态 |
| **是否可以返回上一步** | 不适用（首页无上一页）|
| **返回后内容如何展示** | 不适用 |

#### 步骤 1：素材输入

| 项目 | 内容 |
|------|------|
| **用户看到什么** | 进度条 step 1/6、标题「讲讲你的故事」、大文本输入框、底部字数统计、主按钮「开始诊断」|
| **用户点击什么** | 文本框 → 开始输入；主按钮「开始诊断」→ 触发 AI 诊断 |
| **系统保存什么** | 每 3 秒自动保存到 `localStorage`；点击「开始诊断」后保存到 `Project.material.content` |
| **失败时怎么处理** | 字数 < 100字 → 按钮禁用 + 提示；网络失败 → Toast「保存失败，请检查网络」|
| **是否可以返回上一步** | 可以点击「←」返回首页（有未保存内容时弹窗确认）|
| **返回后内容如何展示** | 刷新后从 `localStorage` 恢复输入内容 |

#### 步骤 2：素材诊断中（loading）

| 项目 | 内容 |
|------|------|
| **用户看到什么** | 进度条 step 2/6、loading 提示「正在分析你的素材...」、进度百分比、禁止返回按钮 |
| **用户点击什么** | 无（按钮禁用）|
| **系统保存什么** | 暂无（等待诊断完成）|
| **失败时怎么处理** | 超时 / 错误 → failed 状态，显示错误 + 「重新诊断」/「修改素材」按钮 |
| **是否可以返回上一步** | **不可以**（防止中断 AI 请求）|
| **返回后内容如何展示** | 不适用 |

#### 步骤 3：诊断结果页

| 项目 | 内容 |
|------|------|
| **用户看到什么** | 进度条 step 2/6、成功提示条、诊断摘要卡片、教练点评卡片、主按钮「看看这些方向 →」|
| **用户点击什么** | 诊断卡片右上角「刷新」→ 重新诊断；主按钮 → 前提选择页 |
| **系统保存什么** | `Project.diagnosis` |
| **失败时怎么处理** | 「AI 无法从这个素材中提取足够的喜剧元素」→ 建议修改素材 |
| **是否可以返回上一步** | 可以点击「← 返回修改素材」→ 素材输入页（素材内容保留）|
| **返回后内容如何展示** | 素材输入框显示之前输入的内容 |

#### 步骤 4：前提选择页

| 项目 | 内容 |
|------|------|
| **用户看到什么** | 进度条 step 3/6、页面标题、上下文提示条（基于选择的诊断方向）、3-5 张前提卡片（单选）、底部计数提示、主按钮 |
| **用户点击什么** | 卡片 → 选中/取消选中；卡片「收藏」→ 标记收藏；卡片「再想想」→ 重新生成这组；主按钮 → 角度选择页 |
| **系统保存什么** | `Project.premise_id`（用户选择后立即保存）|
| **失败时怎么处理** | 某卡片生成失败 → 该卡片单独显示「生成失败，[重新生成]」|
| **是否可以返回上一步** | 可以点击「← 返回诊断」→ 诊断结果页（已选前提仍显示选中态）|
| **返回后内容如何展示** | 已选前提卡片保持橙色边框 + ✓ 标记 |

#### 步骤 5：角度选择页

| 项目 | 内容 |
|------|------|
| **用户看到什么** | 进度条 step 4/6、页面标题、上下文提示条（基于选择的前提）、3-5 张角度卡片（可笑潜力标签：🔥/⚡/❄️）、主按钮 |
| **用户点击什么** | 卡片 → 选中/取消选中；卡片「收藏」/「编辑」/「再想想」；主按钮 → 包袱选择页 |
| **系统保存什么** | `Project.angle_id` |
| **失败时怎么处理** | 同上 |
| **是否可以返回上一步** | 可以点击「← 返回前提」→ 前提选择页（已选角度保留）|
| **返回后内容如何展示** | 已选角度卡片保持选中态 |

#### 步骤 6：包袱选择页

| 项目 | 内容 |
|------|------|
| **用户看到什么** | 进度条 step 5/6、上下文提示条、6-10 张包袱卡片（多选，类型标签：铺垫/包袱/Tag）、底部草稿预览区、主按钮「生成草稿 →」|
| **用户点击什么** | 卡片 → 选中/取消选中；卡片「收藏」/「编辑」/「再想想」；「调整顺序」→ 进入拖拽排序模式；主按钮 → 草稿生成页 |
| **系统保存什么** | `Project.selected_punchline_ids`（每次选择变化立即保存）|
| **失败时怎么处理** | 某包袱生成失败 → 该卡片单独显示失败，可单独重试 |
| **是否可以返回上一步** | 可以点击「← 返回角度」→ 角度选择页（已选包袱保留）|
| **返回后内容如何展示** | 草稿预览区显示已选包袱列表 |

#### 步骤 7：草稿生成中（loading）

| 项目 | 内容 |
|------|------|
| **用户看到什么** | 进度条 step 6/6、loading 提示「正在组装你的段子...」、分步骤进度条（✓ 素材整理完毕 → ✓ 铺垫连接中 → 包袾组装中...）、禁止返回 |
| **用户点击什么** | 无（按钮禁用）|
| **系统保存什么** | 暂无 |
| **失败时怎么处理** | failed 状态 → 建议多选包袱或换方向 + 「重新生成」/「调整包袾选择」|
| **是否可以返回上一步** | **不可以**（防止中断）|
| **返回后内容如何展示** | 不适用 |

#### 步骤 8：草稿生成页

| 项目 | 内容 |
|------|------|
| **用户看到什么** | 进度条 step 6/6、主稿卡片（正文 + 字数）、教练点评条、辅助信息区（素材摘要 / 前提 / 角度 / 包袾列表）、操作按钮组 |
| **用户点击什么** | 「编辑稿子」→ 进入编辑模式；「重新生成」→ 重新调用 AI；「保存草稿」→ 保存当前版本；「标记为完成」→ 保存 + 跳转项目详情；「← 返回包袾」→ 包袾选择页 |
| **系统保存什么** | `Project.final_script`（编辑时实时保存）；`Project.status = 'completed'`（标记完成时）|
| **失败时怎么处理** | AI 无法组合 → failed 提示 + 建议 |
| **是否可以返回上一步** | 可以点击「← 返回包袾」→ 包袾选择页（已选包袱保留）|
| **返回后内容如何展示** | 包袾选择页显示之前选择的包袱 |

#### 步骤 9：完成保存（saving）

| 项目 | 内容 |
|------|------|
| **用户看到什么** | saving 状态 Toast「正在保存...」|
| **用户点击什么** | 无（等待保存完成）|
| **系统保存什么** | `Project.status = 'completed'` |
| **失败时怎么处理** | Toast「保存失败，[重试]」+ 按钮保留 |
| **是否可以返回上一步** | 不可以（等待保存）|
| **返回后内容如何展示** | 不适用 |

#### 步骤 10：项目详情页

| 项目 | 内容 |
|------|------|
| **用户看到什么** | 项目标题、完整创作时间轴（6 个节点）、最终稿全文展示、操作按钮组 |
| **用户点击什么** | 时间轴节点 → 展开/收起详情；「继续创作」→ 从断点继续；「重新开始」→ 清空 + 素材输入页；「复制稿子」→ 剪贴板 + Toast；「删除项目」→ 确认弹窗 |
| **系统保存什么** | 无（读操作）|
| **失败时怎么处理** | 加载失败 → 「重新加载」按钮 |
| **是否可以返回上一步** | 可以点击「← 我的段子」→ 项目列表页 |
| **返回后内容如何展示** | 不适用 |

### 2.3 返回路径与状态保留

| 从页面 | 返回到 | 已选内容保留规则 |
|--------|--------|------------------|
| 诊断结果页 | 素材输入页 | 素材文本保留 |
| 前提选择页 | 诊断结果页 | 前提选中态保留 |
| 角度选择页 | 前提选择页 | 角度选中态保留；前提选中态保留 |
| 包袾选择页 | 角度选择页 | 包袾选中态保留；角度选中态保留；前提选中态保留 |
| 草稿生成页 | 包袾选择页 | 包袾选中态保留；角度/前提保留 |
| 项目详情页 | 项目列表页 | 不适用 |

### 3.2 素材输入页


## 4. 桌面端低保真原型

### 4.1 桌面端布局方案

**MVP 决策：不采用三栏布局**

| 方案 | 优点 | 缺点 | MVP 结论 |
|------|------|------|----------|
| 三栏（左列表 / 中创作 / 右教练）| 随时可见教练提示 | 桌面端用户非核心场景；增加开发成本 | **MVP 不做** |
| 两栏（左列表 / 右创作）| 保留项目切换功能 | 教练提示需内嵌在创作流程中 | **MVP 简化方案** |
| 单栏居中（与移动端相同）| 最简单，与移动端一致 | 无项目列表侧边栏 | **MVP 最低成本** |

**MVP 推荐：单栏居中布局（最大宽度 640px）**

桌面端和移动端使用相同的页面结构，只是：
- 内容最大宽度 640px，居中显示
- 两侧留白用于品牌展示（可选）
- 无侧边项目列表（通过顶部入口访问）

**未来版本（v1.2+）可考虑：两栏布局**

### 6.1 创作流程状态机

```
                         ┌─────────────────────────────────────┐
                         │                                     │
                         │          idle                        │
                         │      （用户刚进入页面）               │
                         │                                     │
                         └──────────────┬──────────────────────┘

                         ┌─────────────────────────────────────┐
                         │                                     │
                         │          editing                     │

                         │                                     │
                         │  [自动保存触发]                       │
                         │       │                             │
                         │       ▼                             │
                         │  saving ──→ saved ──→ editing        │
                         │    │                                │
                         │    └──→ save_failed ──→ editing     │
                         │         [Toast 提醒]                 │
                         └──────────────┬──────────────────────┘
                                        │
                              用户点击「开始诊断/生成/保存」
                                        │
                                        ▼
                         ┌─────────────────────────────────────┐
                         │                                     │
                         │          loading                     │
                         │      （AI 正在处理）                  │
                         │                                     │
                         │  [禁止返回按钮]                       │
                         │  [分步骤进度条]                       │
                         │                                     │
                         └──────────┬──────────────────────────┘
                                    │
                    ┌───────────────┴───────────────┐
                    │                               │
              AI 处理成功                       AI 处理失败
                    │                               │
                    ▼                               ▼
         ┌──────────────────┐           ┌──────────────────────┐
         │                  │           │                      │
         │     success      │           │       failed         │
         │   （显示结果）    │           │   （显示错误 + 建议）  │
         │                  │           │                      │
         │  [自动保存]       │           │  「重新尝试」按钮      │
         │    │             │           │  「返回修改」按钮      │
         │    ▼             │           │                      │
         │   saved          │           │                      │
         │                  │           │                      │
         └────────┬─────────┘           └──────────────────────┘
                  │                              │
        用户点击下一步                          用户点击
                  │                         「重新尝试」
                  │                              │
                  ▼                              ▼
         ┌─────────────────────────────────────────┐
         │                                         │
         │          next_step                      │
         │        （进入下一步骤）                   │
         │                                         │
         └─────────────────────────────────────────┘
```

### 6.2 状态触发来源

| 状态 | 触发来源 |
|------|----------|
| `idle` | 系统：页面加载完成 |
| `editing` | 用户：开始输入/操作 |
| `saving` | 系统：自动保存定时器触发 OR 用户点击保存 |
| `saved` | 系统：保存成功回调 |
| `save_failed` | 系统：保存失败回调 |
| `loading` | 用户：点击「开始诊断/生成」|
| `success` | 系统：AI 处理成功回调 |
| `failed` | 系统：AI 处理失败回调 |
| `next_step` | 用户：点击下一步按钮 |

### 6.3 状态 UI 反馈

| 状态 | Toast | 页面级提示 | 按钮变化 |
|------|-------|-----------|---------|
| `saving` | 「保存中...」| 无 | 无变化 |
| `saved` | 「已保存 ✓」| 无 | 无变化 |
| `save_failed` | 「保存失败，[重试]」| 无 | 重试按钮 |
| `loading` | 无 | loading 页面 | 禁止返回 |
| `success` | 无 | 成功提示条 | 主按钮可点击 |
| `failed` | 无 | failed 卡片 | 显示重试/返回按钮 |

### 6.4 数据保留策略

| 状态 | 数据保留 |
|------|----------|
| `editing` | 实时保留在内存 + 防抖保存到本地 |
| `saving` | 数据已在内存，可安全切换页面 |
| `save_failed` | 数据在内存 + localStorage，显示重试 |
| `loading` | 数据在内存，禁止返回 |
| `failed` | 数据在内存，用户可返回修改 |
| `success` | 数据保存到 Project，返回后保留 |

## 7. 自动保存交互

### 7.1 自动保存机制总览

| 场景 | 触发时机 | 保存位置 | 用户感知 |
|------|----------|----------|----------|
| 用户输入素材 | 停止输入 3 秒后 | `localStorage` + `Project.material` | Toast「已保存 ✓」|
| AI 诊断完成 | 诊断成功后 | `Project.diagnosis` | 无 Toast（自动）|
| 用户选择前提 | 选择后立即 | `Project.premise_id` | 无 Toast（自动）|
| 用户选择角度 | 选择后立即 | `Project.angle_id` | 无 Toast（自动）|
| 用户选择包袾 | 选择变化后立即 | `Project.selected_punchline_ids` | 无 Toast（自动）|
| 用户编辑卡片 | 编辑后 2 秒 | `WorkflowCard.content` | Toast「已保存 ✓」|
| 用户编辑稿子 | 编辑后 2 秒 | `Project.final_script` | Toast「已保存 ✓」|
| 用户标记完成 | 点击后 | `Project.status = 'completed'` | saving → 跳转 |

### 7.2 用户输入素材时的自动保存

```
用户输入文字
      │
      │  每次按键
      ▼
  记录到内存状态
      │
      │  停止输入 3 秒
      ▼
  自动保存到 localStorage
  (key: draft_material)
      │
      ├──→ 成功：顶部 Toast「已保存 ✓」（2 秒后消失）
      │
      └──→ 失败：顶部 Toast「保存失败」（保留 + 重试按钮）
```

### 7.3 AI 生成结果的保存

```
AI 生成完成
      │
      ▼
  解析 JSON
      │
      ├──→ 成功：保存到 Project 对应字段
      │         自动进入下一步
      │         无额外 Toast
      │
      └──→ 失败：显示 failed 状态
                不保存
                等待用户重试
```

### 7.4 用户选择卡片的保存

```
用户点击卡片
      │
      ▼
  更新 UI（选中态）
      │
      │  立即（无延迟）
      ▼
  保存到 Project
  (premise_id / angle_id / selected_punchline_ids)
      │
      ├──→ 成功：继续
      │         无 Toast（太快，不需要提示）
      │
      └──→ 失败：Toast「保存失败，你的选择可能丢失」+ 重试
                保留用户选择的 UI 态
```

### 7.5 用户编辑卡片的保存

```
用户点击「编辑」
      │
      ▼
  进入编辑模式
      │
      │  用户修改内容
      ▼
  记录到内存
      │
      │  停止编辑 2 秒后
      ▼
  自动保存到 WorkflowCard.content
      │
      ├──→ 成功：Toast「已保存 ✓」
      │
      └──→ 失败：编辑框内显示「保存失败，[重试]」
```

### 7.6 保存失败的处理

| 失败类型 | 处理方式 |
|----------|----------|
| 网络保存失败（发送到服务器）| 保留在 `localStorage`，下次网络恢复后重试 |
| localStorage 写入失败 | Toast「存储空间不足，请清理浏览器缓存」|
| JSON 解析失败 | 不保存，显示 failed 状态 |

### 7.7 页面刷新后的恢复

```
页面加载
      │
      ▼
  检查 URL 路由
      │
      ├──→ `/create/material`：检查 `localStorage` 有无 `draft_material`
      │                       有 → 自动填充到输入框
      │                       无 → 空输入框
      │
      ├──→ `/create/diagnosis`：检查 `Project.material` 有无内容
      │                         无 → 跳转 `/create/material`
      │
      ├──→ `/create/angle`：检查 `Project.premise_id`
      │                   无 → 跳转 `/create/premise`
      │
      └──→ `/projects/[id]`：检查 Project 是否存在
                            不存在 → 跳转 `/projects`
```

## 8. 教练感交互设计

### 8.1 每一步开头的教练引导语

| 页面 | 教练引导语 |
|------|-----------|
| 素材输入 | "讲讲你的故事。任何让你觉得好笑、好气、好无奈的事都可以。" |
| 诊断结果 | "✅ AI 教练诊断完成！发现了一些有意思的东西 🎯" |
| 前提选择 | "这个故事可以这样讲。选择一个你最有感觉的方向。" |
| 角度选择 | "从哪个角度来讲？同一个前提，不同角度，笑点完全不同。" |
| 包袾选择 | "这些包袾可以试试。选择你觉得好笑的，加到你的草稿里。" |
| 草稿生成 | "你的 1 分钟开放麦稿 🎤" |

### 8.2 每张卡片的 why_it_works

**位置：** 卡片内容下方，用 `💡 为什么选这个：` 引导

**格式：**
```
💡 为什么选这个：
{why_it_works}
```

**内容要求：**
- 解释为什么这个方向/角度/包袾好笑
- 用用户的语言，不用专业术语
- 50-100 字

**示例（前提卡片）：**
```
💡 为什么选这个：
这个方向把家庭矛盾翻译成了职场段子，受众容易共鸣（职场人太多了），
而且「编制」这个梗自带幽默感。
```

### 8.3 每张卡片的 coach_tip

**位置：** why_it_works 下方，用 `🎯 教练提示：` 引导

**格式：**
```
🎯 教练提示：
{coach_tip}
```

**内容要求：**
- 提供具体的创作建议
- 告诉用户怎么用这张卡片
- 30-80 字

**示例（前提卡片）：**
```
🎯 教练提示：
选择这个方向的话，你的包袾要围绕「外包员工」的身份尴尬来写：
没有正式工福利、被区别对待时没法反驳、干活最多但荣誉最少。
```

### 8.4 每一步选择后的 next_question

**位置：** coach_tip 下方，用 `📌 试试想想：` 引导

**格式：**
```
📌 试试想想：
{next_question}
```

**内容要求：**
- 引导用户深入思考自己的素材
- 问题与当前选择相关
- 1-2 个问题

**示例（角度卡片）：**
```
📌 试试想想：
你能接受的最荒诞的数字对比是什么？比如孙子 1000，你 100？
```

### 8.5 草稿生成后的 coach_review

**位置：** 稿子卡片下方，教练点评卡片内

**结构：**
```
┌─────────────────────────────────────────┐
│ 🎯 教练点评                              │
├─────────────────────────────────────────┤

│                                         │

│ · 第2段铺垫稍长，可删最后一句            │

│                                         │
└─────────────────────────────────────────┘
```

### 8.6 「帮我推荐」机制

**触发条件：** 用户在选择页面停留超过 30 秒，没有做出选择

**触发时机：** 仅在前提选择和角度选择页（非包袾选择，因为包袾是多选）

**UI 展示：**
```
┌─────────────────────────────────────────┐
│                                         │
│  🤔 还在纠结？                          │
│                                         │
│  帮你推荐：                              │
│                                         │
│  ┌───────────────────────────────────┐ │
│  │  🎯 基于你的素材，我推荐第 2 个方向  │ │
│  │                                   │ │
│  │  「{title}」                      │ │
│  │  {description}                    │ │
│  │                                   │ │
│  │  [选这个方向 →]                    │ │
│  └───────────────────────────────────┘ │
│                                         │
│  或者继续看看，也许下一个更好            │
│                                         │
└─────────────────────────────────────────┘
```

**推荐算法逻辑（MVP 简化）：**
1. 默认推荐第 1 个卡片（最符合 AI 判断的优先级）
2. 如果用户之前有收藏，优先推荐收藏的卡片
3. 显示推荐理由：「基于你的素材特征（委屈情绪 + 期待落差）」
